Objectif (cahier des charges)
  Simuler la panne brutale d'un serveur applicatif pendant une charge et
  vérifier que la plateforme continue de servir les clients avec :
    - ≤ 3 requêtes perdues (ERREURS_MAX=3)
    - une période de dégradation < 5 s (DUREE_MAX_SEC=5)

Déroulé du test (exécution réelle du 24/10/2026 19:09)
  1. Vérification préalable : app1 répond sur son IP privée (192.168.59.21:3000)
  2. Sonde continue : curl /resultat?matricule=BF000042 via HAProxy (localhost:8080),
     toutes les 100 ms, horodatage ms
  3. État avant panne : /sante -> HTTP 200 (host: app1, 0.030 s)
  4. Panne simulée : vagrant halt app1 --force (arrêt immédiat = panne matérielle),
     VM poweroff confirmée en 1 s
  5. Observation pendant 20 s pendant laquelle HAProxy doit retirer app1
     (sonde /sante du backend) et router vers app2
  6. État après panne : /sante -> HTTP 200 (host: app2, 0.030 s)

Analyse
  Les 2 requêtes perdues correspondent à la fenêtre de détection de la panne
  par HAProxy (sonde HTTP GET /sante du backend, option httpchk) : entre l'arrêt brut de
